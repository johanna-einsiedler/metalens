About Metalens

Research findings are published as prose and tables inside PDFs. Metalens turns them into structured data that a person has checked, and keeps that data alive as new papers appear.

The problem it addresses

A systematic review or meta-analysis is an enormous amount of careful reading, and the result is frozen on the day it is published. Papers that appear the following month do not change it. Anyone who wants to know what the evidence says two years later has to start again, usually from the same PDFs.

Language models can read those PDFs quickly, but on their own they are not a sound basis for evidence: they make mistakes, and a number with no trail back to its source cannot be checked. Metalens is built around that gap. Every value it produces carries the passage it was read from, and a person decides whether to accept it.

How it works

CaptureA PDF and a preset — the set of fields you want — go to the model you choose. It returns one record per paper.
VerifyEvery value is shown beside the highlighted sentence, table cell or figure it came from. You confirm, correct or reject it.
VisualizeRecords become an analysis table and a dashboard, where each mark can name the rows and quotes behind it.
Stay currentAdd papers, cut a new release, and the dashboards that pin that dataset follow.

A preset is the reusable part: the fields, their types, the prompt and how the results should be laid out for review and analysis. Presets can be shared, so a second team extracting the same kind of evidence starts from the first team's design rather than from a blank page.

What makes a number here checkable

  • Evidence. Each value is tied to a verbatim quote with its page, so you can see exactly what the model read. A value with no evidence is visible as such.
  • Verification history. Who confirmed or corrected a record, when, and with what note. A dataset carries a credibility label that reflects how much of it a person has actually checked.
  • The model is recorded. Which model, which prompt and which preset version produced a record are stored with it, so an extraction can be repeated or compared.
  • Cross-checks. Where a dataset has a companion — for example claims checked against the regression tables they cite — disagreements are surfaced rather than smoothed over.

Publishing and citing

A dataset can be published as a frozen release: the records, the evidence quotes, the preset and the verification history, written out as static files. Releases go to a public datasets repository on GitHub and can be given a DOI on Zenodo, so a figure in a paper can point at the exact state of the data it was drawn from. Published datasets are listed in the data catalogue.

Dashboards built on a release — inside Metalens or in your own code on your own site — are listed on the dashboards page. A dashboard pins a release, so it never changes under you; when the dataset grows, you update it deliberately.

Your data

Papers, datasets and presets are private to you until you publish. API keys are held in memory for the length of a run and never written to disk. Without an account, everything you upload is deleted two hours after your last activity. The FAQ sets out in detail what is stored, for how long, what reaches the model provider, and what you may lawfully upload.

Open source, and running it yourself

Metalens is open source under the MIT licence: github.com/johanna-einsiedler/metalens. You can run the whole thing on your own machine, with an embedded database and no account, and point it at a local model server — in that setup neither the PDF nor its text leaves your computer. This matters where an institutional data agreement rules out a hosted service.

MASEMiner

MASEMiner is the same engine with a narrower job: extracting the correlation matrices and study metadata that meta-analytic structural equation modelling needs. If that is your task, start there — the presets and the review screen are built for it.

Metalens is research software, developed in the open. Questions, bugs and feature requests are welcome as issues on GitHub.
